  1. **只读**：不发邮件、不删邮件、不移动邮件、**不置已读**。
     拉取一律用 `BODY.PEEK` 一类不改变标志的方式；不得用 `RFC822` 之类会把邮件标成已读的拉取方式。
  2. **配置外置**：账号与 IMAP 授权码只存在用户本机的正式配置文件里。
     让用户从 `scripts/mail_accounts.example.json` 复制成 `mail_accounts.json` 后填写；
     你不得把真实账号、授权码、服务器地址写进任何回复或文件。
  3. **不假装抓了**：授权码为空、IMAP 连不上、账号缺字段 → 跳过该账号并**明确说明原因**，
     不得报告「已完成」。
  4. **增量**：状态文件记上次检查时间与最大 UID；只抓 UID 更大的邮件。
     不要为了「保险」每次全量重拉 —— 会重复落盘、拖慢邮箱。
  5. **查重**：附件按内容 MD5 去重，同天同主题加 UID 后缀，正文内联小图（签名、Logo）不当业务附件。
  6. **黑名单要说明**：系统通知、验证码、退信、订阅类命中即跳过，但必须在报告里说明「为什么跳过」，
     不能当成漏抓。
  7. **落盘根目录**：环境变量 `TENDER_MAIL_OUTPUT_DIR` > 配置文件 `output_dir` > 默认桌面。
     若 Trade 以服务 / 系统账户运行，**不得用 `~` 解析桌面**，必须让用户写绝对路径。

# B2B 招标邮件抓取归档

把邮箱里的招标 / 询价邮件连同附件**只读**抓下来，按天归档。只负责「抓下来」，不负责「整理成询价单」（那是 `b2b-tender-processing`）。

## 输入

- 邮箱 IMAP 配置（用户在 `mail_accounts.json` 里填写，从示例文件复制）
- 时间窗口：今天 / 近 N 天 / 增量
- 落盘根目录（建议用户显式给绝对路径）

## 输出

- `<落盘根目录>/<日期>/<日期>_<主题>.txt`：邮件正文与元信息
- `<落盘根目录>/<日期>/<日期>_<主题>_附件/`：附件
- 近 N 天模式额外按「询价 / 招标」分目录
- 一份统计：抓取数、附件数、跳过数与原因、输出目录

## 处理方式

> **语言**：脚本输出支持中英双语 —— 用户用英文对话时加 `--lang en`
> （或设 `TRADE_LANG=en`），默认中文。

| 脚本 | 用途 | 触发场景 |
|---|---|---|
| `fetch_recent.py` | 近 N 天补抓（默认 2 天），按主题分类 | 首次配置后、停机回来、查漏 |
| `monitor_inbox.py` | 增量监控，无新邮件静默 | 挂定时任务日常跑 |
| `backfill_attachments.py` | 只补缺失附件 | 早期只记了附件名、没下本体 |

三者共用 `tender_mail_core.py`：配置加载、增量过滤、黑名单、`BODY.PEEK` 拉取、解析、落盘、MD5 去重。

## 落盘规则

- 同天同主题两封邮件 → 第二封文件名加 `_<UID>`，不互相覆盖。
- 附件按内容 MD5 去重，同内容只留一份；同名不同内容加序号。
- 正文内联小图（`Content-ID` 或 `inline` 的图片）不进附件目录。
- 文件名里的非法字符（`/ \ : * ? " < > |` 与控制字符）写入前替换成 `_`。

## 使用限制

- 只支持 IMAP（含 IMAP over SSL）；不支持仅提供网页版或专属 API 的邮箱。
- 只选收件箱，不处理其它文件夹。
- 不解析邮件正文里的表格 / 附件内容 —— 那属于后续整理步骤。
