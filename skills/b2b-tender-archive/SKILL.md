# B2B 批量解压与归档清理

批量解压压缩包、处理嵌套包，解压后按需归组清理。

## 输入

- 要处理的目录（压缩包所在位置）
- 模式：A 删包归档 / B 就地解压不删包
  - 招标批量包：没明说按 **A**
  - 单文件 / 非招标：默认 **B**（不删用户原包）

## 输出

- 解压产物
- 报告：成功数、失败清单与原因、进回收站数、残留数
- 可选：编号归组计划（只出计划，不执行）

## 处理方式

> **语言**：脚本输出支持中英双语 —— 用户用英文对话时加 `--lang en`
> （或设 `TRADE_LANG=en`），默认中文。

```bash
# 先看规模，不动文件
python scripts/extract_archives.py --root "<目录>" --dry-run

# 招标批量包：原包进回收站（脚本的默认模式就是 A）
python scripts/extract_archives.py --root "<目录>" --mode A

# 单文件 / 非招标：保留原包
python scripts/extract_archives.py --root "<目录>" --mode B
```

| 阶段 | 做什么 | 失败/异常时 |
|---|---|---|
| 摸底 | 数量、总大小、0 字节损坏数 | — |
| 安全核查 | 两次快照对比条目数 | 不一致 → 停手，报「目录正在变化」 |
| 第一轮 | 解压 + 按模式处理原包 | 单包失败记原因，不中断整批 |
| 嵌套迭代 | 重扫 → 再解压，最多 5 轮 | 到上限仍有残留 → 明确报告 |
| 最终验证 | 全目录扫描残留 | — |
| 编号归组 | 只出计划（`--plan-grouping`） | 需用户确认后才执行 |

## 使用限制

- 7z / rar 依赖系统已装的压缩工具（`7z` / `unrar`）；缺失时该包标失败，不硬解。
- 回收站：macOS 用 `~/.Trash`，Linux 走 XDG 回收站，Windows 走 Shell API；
  都不可用时**不删**，只报告。
- 不做「按清单匹配文件」（那是 `b2b-tender-doc-match`）。
